# Hiperssora · Guía de componentes del TPV

Catálogo de todos los componentes de la **caja registradora** de Hiperssora: la pantalla que
usan los cajeros y las cajeras para cobrar a los clientes.

- **Maqueta.** Los componentes son presentacionales: reciben datos por props y exponen
  callbacks (`onSelect`, `onCharge`…). Lo único conectado es el bloqueo con PIN, el
  **buscador**, que consulta el catálogo real de [Nutriinfo](https://www.nutriinfo.es), y el
  **ticket**, al que se encolan los productos buscados, escaneados o elegidos en una sección. En Storybook, el buscador usa datos simulados.
- **Solo escritorio y pantalla táctil.** No es responsive. Ancho mínimo de 1280 px y áreas
  táctiles de al menos 56 px.
- **Modales, nunca desplegables.** En una pantalla táctil, un menú desplegable abierto se
  cierra o se activa por error con el siguiente toque. Toda elección se hace en un modal con
  fondo gris, que se cierra con la X, pulsando fuera o eligiendo una opción.
- **Teclado.** Todo se podrá manejar con atajos (ver _Barra de atajos_).

## La pantalla

```
┌──────────────────────────────────────────────────────────────────────┐
│ PosHeader     Logo                Clock · Clientes en pausa · Cajero │
├─────────────────────────────────────────────┬────────────────────────┤
│ TicketPanel (≈70 %)                         │ CheckoutPanel (≈30 %)  │
│  ┌ ProductSearch ─────────────────────────┐ │  TicketTotal           │
│  └────────────────────────────────────────┘ │  [ Cobrar ]            │
│  ┌ TicketList ────────────────────────────┐ │  SelectedLinePanel     │
│  │ TicketLineRow                          │ │  SectionButtons        │
│  │ TicketLineRow                          │ │  AddBagButton          │
│  └────────────────────────────────────────┘ │  TicketActions         │
├─────────────────────────────────────────────┴────────────────────────┤
│ ShortcutsBar   Esc Salir · ↑ Anterior · ↓ Siguiente · F1 Cobrar …    │
└──────────────────────────────────────────────────────────────────────┘
```

Al entrar, la caja está **bloqueada** (ahora, temporalmente, arranca desbloqueada) (`LockScreen`) y da la bienvenida al cajero hasta que
introduce su PIN. **Bloquear pantalla**, en el modal del cajero, la vuelve a bloquear.

Al tocar el buscador se abre `ProductSearchDialog`, el modal de búsqueda con predictivo. Los
botones de sección abren `SectionCatalogDialog` a pantalla completa y, al elegir un producto, la
báscula (`ScaleDialog`) lo pesa antes de añadirlo. La pistola lectora añade
productos en cualquier momento.

Al pulsar **Cobrar** se abre `PaymentMethodDialog`, que lleva a `CardPaymentDialog` o a
`CashPaymentDialog`.

nombre del componente en el código; el buscador de la barra lateral también encuentra los

## Estructura del código

```
src/
├── app/                    # Rutas de Next.js: "/" renderiza PosScreen con datos de ejemplo
├── components/
│   ├── ui/                 # Primitivas de shadcn/ui (generadas por la CLI)
│   ├── common/             # Componentes reutilizables (Logo, ProductThumbnail)
│   └── pos/                # Componentes del TPV, una carpeta por zona de la pantalla
│       ├── layout/         # PosScreen, PosApp
│       ├── lock/           # Pantalla de bloqueo
│       ├── header/
│       ├── ticket/
│       ├── checkout/
│       ├── sections/       # Frutería, Verdulería, Panadería
│       ├── payment/
│       └── shortcuts/
├── config/               # Atajos de teclado (shortcuts.ts) y PIN de la maqueta (auth.ts)
├── hooks/                  # Hooks de React (useNow, useProductSearch)
├── lib/                    # Formato, totales del ticket, búsqueda y cliente de la API de Nutriinfo
├── mocks/                  # Datos de ejemplo de la maqueta (catálogo, tickets, cajero)
└── types/pos.ts            # Tipos del dominio: Product, TicketLine, PausedTicket…
```

## Convenciones

- **Una story por componente**, junto a él (`numpad.tsx` + `numpad.stories.tsx`). El título de la
  story refleja la zona de la pantalla: `TPV/<Zona>/<Componente>`.
- **Documentación en el código.** La descripción de cada componente y de cada prop sale de sus
  comentarios JSDoc, y Storybook la muestra en la pestaña _Docs_.
- **Componentes sin datos propios.** Reciben todo por props; los datos de ejemplo viven en
  `src/mocks` y solo los importan las stories y la página.
- **El formato no se hace en los componentes.** Precios, cantidades y horas pasan por
  `@/lib/format`, y los totales por `@/lib/ticket`.
- **Cada carpeta tiene un `index.ts`** que exporta sus componentes:
  `import { Numpad } from "@/components/pos/checkout"`.
